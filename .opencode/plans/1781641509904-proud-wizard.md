# Plan: Standards-Aware Development Workflow (`/plan`, `/build`, `/review` Commands)

## Problem

`AGENTS.md` currently mixes two concerns:

1. **Agent behaviour rules** — how the agent communicates, uses tools, and manages files
2. **Coding standards** — how code should be written (naming, typing, testing, etc.)

There is no structured workflow that ensures:
- The plan agent incorporates coding standards when writing implementation plans
- The build agent follows acceptance criteria and runs verification commands
- Finished work is reviewed against standards before being considered done

---

## Solution

Three custom slash commands (`/plan`, `/build`, `/review`) that form a lightweight, optional development workflow. No new agent files needed — the commands augment the existing built-in `plan` and `build` agents.

### New file: `STANDARDS.md`

Contains all coding standards extracted from `AGENTS.md`. `AGENTS.md` retains only agent-behaviour rules.

**Sections extracted to `STANDARDS.md`:**
- Function Design
- Domain
- Typing
- Naming
- Documentation
- Imports
- Testing

**Sections remaining in `AGENTS.md`:**
- General
- File System
- Git
- GitHub
- Shell (PowerShell)

`STANDARDS.md` is deployed globally to `~/.config/opencode/STANDARDS.md` by the sync script.

---

### Plan file format

Written by the plan agent to `.opencode/plans/<timestamp>-<slug>.md`:

```markdown
# Plan: <feature name>

## Implementation Approach

<description of what changes will be made and why>

## Acceptance Criteria

- [ ] <testable statement>
- [ ] <testable statement>

## Verification Commands

```bash
<command 1>
<command 2>
```
```

---

### `/plan` command — targets `plan` agent

Instructs the plan agent to:
1. Read `STANDARDS.md` (injected via `!cat` shell output — project root first, global fallback)
2. Write a plan file to `.opencode/plans/<timestamp>-<slug>.md` containing:
   - Implementation approach
   - Acceptance criteria (checklist of testable statements)
   - Verification commands (test, lint, build, etc. — sourced from project config)

---

### `/build` command — targets `build` agent

1. Reads the most recent plan file via `!ls -t .opencode/plans/*.md | head -1 | xargs cat`
2. Instructs the build agent to:
   - Implement the feature as described in the plan
   - After implementing, run every command under **Verification Commands**
   - Confirm each acceptance criterion is met
   - Fix any failing criterion or command before stopping

---

### `/review` command — no fixed agent target (runs in whichever agent is active)

1. Reads the most recent plan file via `!` syntax
2. Reads `STANDARDS.md` via `!cat` (project root first, global fallback)
3. Instructs the agent to:
   - Run all verification commands from the plan file and report results
   - Check each acceptance criterion against the current code
   - Check changed files against `STANDARDS.md`
   - List all violations with file + line references
   - If violations are found: describe each one; user tabs to `build` to fix, then returns to `/review`
   - Loop until all criteria pass and no violations remain

## Acceptance Criteria

- [ ] `STANDARDS.md` exists at the project root with all coding rules from AGENTS.md
- [ ] `AGENTS.md` contains only agent-behaviour rules (General, File System, Git, GitHub, Shell)
- [ ] `.opencode/commands/plan.md` exists with `agent: plan` frontmatter
- [ ] `.opencode/commands/build.md` exists with `agent: build` frontmatter
- [ ] `.opencode/commands/review.md` exists
- [ ] `/plan` injects STANDARDS.md and produces a plan file with all three sections
- [ ] `/build` reads the most recent plan file and runs verification commands after implementing
- [ ] `/review` reads the plan file and STANDARDS.md, runs verification commands, and reports violations
- [ ] `scripts/sync-skills.ps1` deploys `STANDARDS.md` → `~/.config/opencode/STANDARDS.md`
- [ ] `scripts/sync-skills.ps1` deploys command files → `~/.config/opencode/commands/`
- [ ] `scripts/sync-skills.sh` does the equivalent in bash
