# Plan: Fix merge-json.js — narrow catch + PS1 error propagation

## Context

The merge-based sync was already implemented (commit `50fc821`). Two bugs were found during post-implementation investigation that can silently drop the `plugin` key:

### Root cause of reported regression

Test 3 in the verification run (delete global file → run sync) left `~/.config/opencode/opencode.json` without a `plugin` key. When the user subsequently ran sync, the merge correctly preserved the now-absent key (nothing to preserve). The plugin key was manually restored during investigation so the global config is currently correct.

### Bug 1 — `merge-json.js` catch block is too broad

```js
// CURRENT (broken):
let existing = {};
try { existing = JSON.parse(fs.readFileSync(targetPath, 'utf8')); } catch (_) {}
```

The catch silently swallows **JSON parse errors** in addition to ENOENT. If the global config is malformed, `existing` falls back to `{}`, the merge proceeds with no global context, and all global-only keys (including `plugin`) are silently wiped. The script exits 0 — no indication of failure.

**Fix:** only catch ENOENT; rethrow everything else.

```js
let existing = {};
try {
  existing = JSON.parse(fs.readFileSync(targetPath, 'utf8'));
} catch (err) {
  if (err.code !== 'ENOENT') throw err;
}
```

### Bug 2 — `sync-skills.ps1` doesn't check `$LASTEXITCODE` after `node`

`$ErrorActionPreference = 'Stop'` only applies to PowerShell cmdlet errors, not native process exit codes. A failing `node` call (e.g., node not in PATH, uncaught exception in merge-json.js) is silently ignored and the script exits 0.

The SH script is fine (`set -euo pipefail` propagates non-zero exits).

**Fix:** add an explicit `$LASTEXITCODE` check after the node call in sync-skills.ps1:

```powershell
node $MergeScript $GlobalOpenCodeJson $OpenCodeJson
if ($LASTEXITCODE -ne 0) { throw "merge-json.js failed (exit $LASTEXITCODE)" }
```
