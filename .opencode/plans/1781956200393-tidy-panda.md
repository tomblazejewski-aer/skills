# AFK Workflow — STANDARDS.md as Single Source of Truth + Information Flow Diagram

## Problem

Two gaps in the current workflow:

1. **Standards gap**: The concrete mechanical criteria we added to `afk-reviewer-standards.md` only exist in the reviewer's instructions. The builder reads STANDARDS.md (abstract rules) and has no way to know the stricter interpretation the reviewer applies. The planner also reads STANDARDS.md, so it cannot guide the plan with concrete constraints. Result: builder writes code in good faith → reviewer flags violations the builder never knew about → unnecessary review/fix cycles.

2. **Visibility gap**: No diagram exists showing what each phase reads/writes and how context flows through the workflow. Without this it is easy to introduce future gaps (like the one above) without noticing.

## Implementation Approach

### Part 1 — STANDARDS.md as single source of truth

Expand two sections in `STANDARDS.md` with the concrete, unambiguous criteria currently buried in the reviewer:

- **Function Design**: what "single concern" means in practice (>~50 lines is a violation) and what "return values not side effects" means concretely (non-trivial `None`-returning functions are violations, with named exceptions)
- **Testing**: what "assert on full objects" means concretely (single `assert result == expected` with pre-constructed expected object; multiple separate assert calls on individual fields is a violation)

Then simplify `afk-reviewer-standards.md` step 2 to remove duplication — the reviewer should apply STANDARDS.md mechanically; it no longer needs its own copy of the criteria.

### Part 2 — Information flow diagram

Create `docs/afk-loop.md` — a Mermaid diagram + companion table showing what each phase reads and writes.

The diagram must make the following explicit:
- `/plan` reads STANDARDS.md + skills; writes the plan file
- `afk-orchestrator` BUILD reads plan + STANDARDS.md + CONTEXT.md + AGENTS.md + tdd skill; writes source code + plan checkboxes
- `afk-reviewer-correctness` reads plan + runs verification commands; emits VERDICT
- `afk-reviewer-standards` reads STANDARDS.md + full changed files; emits VERDICT
- `afk-reviewer-architecture` reads CONTEXT.md + git diff + full changed files; emits VERDICT
- Orchestrator DECIDE reads 3 verdicts; loops back to BUILD or emits COMPLETE
