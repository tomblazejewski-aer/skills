# AFK Loop — Merge Builder Into Orchestrator (Fix Context Loss)

## Background

The `/afk` command was implemented with a separate `afk-builder` subagent invoked via the Task tool each cycle. Subagents start with a fresh context on every invocation, so the builder loses accumulated understanding of the codebase, what it tried, and what failed between review cycles. The fix is to remove the builder subagent and have the orchestrator do the building inline within its own persistent session.

## Implementation Approach

Delete `afk-builder.md` and rewrite `afk-orchestrator.md` to incorporate the build logic directly. The orchestrator:

1. Gets full edit + bash permissions (same as the former builder — except no `git commit` / `git push`)
2. Loads the TDD skill itself
3. Executes the BUILD step inline (no Task invocation) — reads plan, addresses FAIL findings from prior cycles first, TDD-implements remaining unchecked criteria one at a time, marks each `[x]` in the plan file, runs verification commands
4. If verification commands fail after honest effort → emits `STATUS: BUILD_FAILED` and exits
5. Still invokes the 3 reviewers in parallel via the Task tool (they don't need persistent context — they're stateless graders)

The state machine steps, reviewer agents, and plan file structure are otherwise unchanged.

### New orchestrator permission model

```yaml
permission:
  edit: allow
  task:
    "*": deny
    "afk-*": allow
  skill: allow
  bash:
    "*": allow
    "git commit*": deny
    "git push*": deny
    "git branch*": deny
```

### New state machine (step 1 changes; all others unchanged)

```
STEP 0 — LOCATE PLAN (unchanged)

STEP 1 — BUILD (now inline — no Task invocation):
  - Load the TDD skill
  - Read PLAN_FILE in full; run git diff to understand current state
  - If prior ## Review Cycle sections exist, note every VERDICT: FAIL finding
    → address those findings FIRST before any remaining unchecked criteria
  - TDD loop: one criterion at a time (red → green → mark [x] in plan)
  - Run all verification commands from the plan
  - If all pass → continue to STEP 2
  - If any fail after honest effort → emit STATUS: BUILD_FAILED, exit

STEP 2 — REVIEW (3 parallel Tasks — unchanged)
STEP 3 — COLLECT + UPDATE PLAN (unchanged)
STEP 4 — DECIDE (unchanged)
STEP 5 — COMPLETE (unchanged)
```
