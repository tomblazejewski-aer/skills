# AFK Loop — Autonomous Build + Multi-Reviewer Cycle + Sync Script Fix

## Implementation Approach

Add a `/afk` command and 5 agent files to the existing `plan → build → review` workflow. The `/afk` command delegates to an `afk-orchestrator` agent that drives an autonomous loop: implement all unchecked plan criteria → run 3 parallel specialist reviewers → append findings to the plan file → repeat until all reviewers agree.

The plan file (`.opencode/plans/<timestamp>-<slug>.md`) acts as the shared state bus: the orchestrator reads it to know what to build and appends `## Review Cycle N` sections after each cycle. On retry, the builder reads the updated plan (including prior review findings) to know what to address next.

### New files

| File | Role |
|---|---|
| `.opencode/commands/afk.md` | `/afk` entry point; sets `agent: afk-orchestrator` in frontmatter |
| `.opencode/agent/afk-orchestrator.md` | Primary agent; owns the loop state machine, invokes subagents, appends review cycles to plan |
| `.opencode/agent/afk-builder.md` | Subagent; implements all unchecked criteria from the plan using TDD (mirrors `/build` logic); can edit files and run tests |
| `.opencode/agent/afk-reviewer-correctness.md` | Subagent; checks acceptance criteria + runs verification commands; read-only (`edit: deny`) |
| `.opencode/agent/afk-reviewer-standards.md` | Subagent; checks STANDARDS.md compliance; read-only (`edit: deny`) |
| `.opencode/agent/afk-reviewer-architecture.md` | Subagent; checks design quality, testability, and module structure; read-only (`edit: deny`) |

### Modified files

| File | Change |
|---|---|
| `CONTEXT.md` | Add `AFK Loop`, `Review Cycle`, `Reviewer` terms |
| `scripts/sync-skills.ps1` | Add block to copy `.opencode/agent/*.md` → `~/.config/opencode/agent/` |

### Sync script gap

The current sync scripts deploy:
- `skills/` (from `plugin.json` registry)
- `commands/` (from `.opencode/commands/`)
- `AGENTS.md`, `opencode.json`, `STANDARDS.md`

They do **not** deploy `.opencode/agent/`. Without this fix, `/afk` would appear in global commands (because `commands/afk.md` is copied) but `afk-orchestrator` would be missing — causing a broken experience in any repo that uses the global config.

The fix mirrors the existing `commands/` deploy pattern: copy all `.md` files from `.opencode/agent/` to `~/.config/opencode/agent/`.

### Orchestrator state machine

```
LOOP:
  STEP 1 — BUILD
    Invoke afk-builder (Task subagent)
    → BUILT: continue to STEP 2
    → BUILD_FAILED: emit STATUS: BUILD_FAILED, exit

  STEP 2 — REVIEW (3 subagents in parallel, single Task message)
    Invoke: afk-reviewer-correctness
            afk-reviewer-standards
            afk-reviewer-architecture
    Each returns: VERDICT: PASS | FAIL + findings (file:line refs where applicable)

  STEP 3 — COLLECT + UPDATE PLAN
    Append to the plan file:
      ## Review Cycle N
      ### Correctness Reviewer — VERDICT: PASS | FAIL + findings
      ### Standards Reviewer   — VERDICT: PASS | FAIL + findings
      ### Architecture Reviewer — VERDICT: PASS | FAIL + findings
      **Overall: PASS | FAIL**

  STEP 4 — DECIDE
    All 3 PASS → emit STATUS: COMPLETE, exit loop
    Any FAIL   → increment cycle counter, return to STEP 1
               (builder reads updated plan, sees prior findings)
```

### Plan file structure after review cycles

```markdown
### Acceptance Criteria
- [x] behavior A
- [x] behavior B

### Verification Commands

---

### Architecture Reviewer
VERDICT: PASS

```

### Permission model

| Agent | Edit files | Run bash |
|---|---|---|
| `afk-orchestrator` | Plan file only | Limited (ls, find plan; no source edits) |
| `afk-builder` | Yes (all) | Yes (all, except `git commit` / `git push`) |
| `afk-reviewer-correctness` | No (`edit: deny`) | Yes (verification commands from plan) |
| `afk-reviewer-standards` | No (`edit: deny`) | No |
| `afk-reviewer-architecture` | No (`edit: deny`) | No |

### Agent invocation pattern

The orchestrator uses the Task tool to invoke subagents by name. Its `task` permission allows only `afk-*` agents (all others denied), mirroring the Chronos `issue-dispatcher` fence. The three reviewers are launched in a single message (parallel Task calls).

### Terms to add to CONTEXT.md

- **AFK Loop**: The autonomous build-review cycle driven by `/afk`. Runs until all Reviewers agree the feature is correctly implemented. _Avoid_: autonomous workflow, dispatch loop.
- **Review Cycle**: One iteration of the AFK Loop — one build pass followed by 3 parallel Reviewer verdicts. Findings appended to the plan file as `## Review Cycle N`. _Avoid_: review round, iteration.
- **Reviewer**: A read-only subagent with a fixed focus area (Correctness, Standards, or Architecture) that emits a `PASS | FAIL` verdict with specific findings. _Avoid_: verifier, reviewer agent.
