# AFK Loop — Fix Global STANDARDS.md Lookup in Subagents

## Root Cause

Two agents reference the global `STANDARDS.md` fallback but can't reach it:

1. **`afk-reviewer-standards.md`** — bash is restricted to `echo*`, `git diff*`, `git status*`. It cannot run `cat ~/.config/opencode/STANDARDS.md`. Its instruction says "fall back to `$HOME/.config/opencode/STANDARDS.md`" but the Read tool doesn't expand shell variables. `$HOME` is treated as a literal string. Result: file not found → silently skips standards checking (returns `VERDICT: PASS` with a note).

2. **`afk-orchestrator.md`** — has full bash, but the instruction says `read STANDARDS.md (or ~/.config/opencode/STANDARDS.md)`. The agent may use the Read tool with `~/.config/opencode/STANDARDS.md` as the path, which also doesn't expand `~`. The Read tool requires a fully resolved path.

**Key principle:** Shell commands (`cat`, `bash`, PowerShell) DO expand `~` and `$HOME`. The Read tool does NOT.

## Implementation Approach

### `afk-reviewer-standards.md`

1. Add `cat ~/.config/opencode/STANDARDS.md` to the bash allowlist.
2. Update the load-standards instruction to say: "If `STANDARDS.md` is not in the project root, use bash to read the global fallback: `cat ~/.config/opencode/STANDARDS.md`."

### `afk-orchestrator.md`

Update the STANDARDS.md hint in the BUILD step to say: "If `STANDARDS.md` is not in the project root, use bash: `cat ~/.config/opencode/STANDARDS.md`."
